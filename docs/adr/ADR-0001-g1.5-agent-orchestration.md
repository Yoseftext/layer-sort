# ADR-0001 — G1.5 Agent Orchestration, QA Automation and Shizuku Preparation

- **Date:** 2026-10-24
- **Status:** Accepted with known limitations by owner 2026-10-25; PR merge not approved
- **Scope:** G1.5 only. Does not authorize G2 gameplay, Firebase, billing,
  production signing, or any change to `main`.
- **Related:** `docs/current/04-AGENT-OPERATIONS.md`,
  `docs/current/05-QA-TEST-CATALOG.md`,
  `docs/current/06-SHIZUKU-TERMUX.md`, `AGENTS.md`.

## Context

G1 proved a Godot Standard GDScript APK builds in CI, installs on the OPPO, and
renders a portrait scene with screenshot + logcat evidence. The owner has now
authorized G1.5: prepare the OpenCode environment so future gates can be
developed and tested by coordinated specialist agents with strict, auditable QA
instead of ad-hoc commands.

The installed environment is OpenCode `2.1.4`. Its V2 configuration uses
`agents` / `permissions` / `policies` and project-scoped Markdown agents under
`.opencode/agents/`; V1 `permission`/`task` fields are deprecated and must not
be used.

## Decision

1. **Introduce gate G1.5** between G1 and G2 for agent orchestration, QA
   automation, tooling and optional Shizuku diagnostics. G2 stays blocked until
   the owner authorizes it separately.
2. **Adopt the three operating documents** `04` (agent operations and
   controlled autonomy), `05` (QA test catalog and report fields) and `06`
   (Shizuku → Termux policy) as part of `docs/current/`, without changing
   B01–B15 or the G0–G9 gate conditions.
3. **Use native OpenCode V2 subagents only.** Start with `repo-auditor`,
   `device-qa`, `visual-auditor` and `reviewer` in `.opencode/agents/`, with an
   explicit permission rule per role, `mode: subagent`, no nested delegation,
   and no hidden or perpetual agents. The primary agent keeps orchestration;
   subagent depth stays at the OpenCode default of 1.
4. **Enforce high-risk rules in configuration, not only prose.** Project
   `policies` hard-deny `git push --force/-f/--mirror`, `gh pr merge`,
   `rm -rf`, and SSH key reads; each subagent also has narrow `permissions`.
5. **QA workflows are repository-local scripts** under `tools/qa/` with
   `--help`, `--dry-run` where changes could happen, bounded timeouts, machine
   JSON and human Markdown reports, strict `PASS|FAIL|SKIP|UNVERIFIED` states,
   and deliberate negative-test fixtures so the checks can genuinely fail.
6. **Device tests keep the single-phone rule**: all phone-mutating runs go
   through the existing `agentctl`/`phone-queue` lock. GitHub Actions remains
   the build host; the phone never runs builds.
7. **Shizuku stays optional and un-elevated.** The first step is a read-only
   capability check and the owner's manual `rish` export/authorization; no
   privileged bridge, root claim, or persistent daemon is created until the
   owner approves a separate narrow wrapper.
8. **Every new dependency** is recorded in `tools/inventory.md` with source,
   version, license, checksum or lock reference, architecture, risk, rollback
   and test result. No paid APIs, accounts, billing, global OS upgrades, or
   `curl | sh` installers.

## Consequences

Owner acceptance is for the G1.5 operational foundation, **not** an all-tests
PASS or permission to merge PR #1/#2. `G15-QA-001` stays OPEN with one bounded
focus/overlay follow-up in `docs/current/05-QA-TEST-CATALOG.md`. OpenCode shell
pattern denies are defense-in-depth, not a substitute for protected Git refs or
owner merge approval. Shizuku's native-Termux `uid=2000(shell)` was verified by
owner report; Debian proot and QA integration are unverified, optional, and no
bridge is approved. No G2 gameplay authorization is implied.

- Future gates inherit a reproducible QA report format and an agent roster with
  auditable permissions.
- Debug reproducibility improves because APK/commit/CI-run/cert/installed-hash
  provenance becomes a first-class check.
- Shizuku may remain `NEEDS_OWNER_AUTH` or `OPTIONAL_BLOCKED`; G1/G2 work
  continues on ADB/Appium and is not blocked by it.
- The project gains one extra CI job for repository-local QA tool tests
  (no device access).

## Rollback

- Revert the G1.5 PR commit range or close the stacked PR; `main` and
  `spike/godot-csharp-android` are untouched.
- `.opencode/` configuration is additive and project-scoped: deleting it
  returns OpenCode to the built-in agent defaults.
- QA scripts are standalone: removing `tools/qa/` does not affect the G1 build
  workflow, `agentctl`, `phone-queue`, ADB, Appium, or the supervisor.
- Shizuku remains opt-in; no state was changed on the phone for it.
